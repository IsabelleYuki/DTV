# 小红书直播支持

小红书在本分支中是独立的第五个平台。收藏使用主播的固定用户 ID，而不是某一场直播的 `roomId`；每次刷新和播放都会重新解析当前场次，因此主播再次开播并更换房间后不需要重新收藏。

## 使用方法

1. 在浏览器登录自己的小红书账号。
2. 打开浏览器开发者工具的 Network（网络）面板，刷新小红书网页，选择一个发往 `xiaohongshu.com` 的请求并复制完整 `Cookie` 请求头。
3. 在 DTV 的“小红书”页粘贴 Cookie。完整功能要求其中包含 `a1` 和 `web_session`。
4. 先点“测试连接”，成功后选择安全保存；若系统安全存储不可用，可明确选择“仅本次会话”。
5. 输入主播主页链接、手机分享短链接、24 位 UID、小红书号或昵称。昵称存在多个结果时需要手动选择。
6. 添加关注后，从左侧关注列表打开主播。DTV 会先查询当前直播状态和本场 `roomId`，再获取播放流。

Cookie 输入框默认隐藏内容，可以临时显示。保存或测试后，输入框中的值会被清空。更换 Cookie 直接重新保存，清除则会同时删除安全存储或当前会话中的凭据。

## 凭据和数据安全

- Cookie 只在 Rust/Tauri 后端处理。React 前端只接收配置状态、公开主播字段和安全错误信息。
- 持久化使用系统原生凭据存储；macOS 对应 Keychain。失败时会返回错误，不会降级写入 `localStorage` 或普通配置文件。
- “仅本次会话”模式只把 Cookie 保存在进程内存中，退出应用即失效。
- 配置导出和局域网同步对关注对象使用公开字段白名单。`cookie`、`token`、签名头及任意未知字段不会进入传输数据。
- 播放代理只对精确的 `xiaohongshu.com` 子域发送 Cookie；`xhscdn.com` 媒体域只接收 Referer/Origin，仿冒域不会获得小红书请求头。
- Cookie、签名值和请求头不会写入日志。不要在 issue、聊天或截图中公开 Cookie。

## 错误含义

| 提示类型 | 含义与处理 |
|---|---|
| 格式错误/缺少字段 | Cookie 不是完整请求头，或缺少 `a1`、`web_session`；重新复制完整值 |
| 未配置 | 先在小红书页设置 Cookie |
| 登录失效 | 浏览器会话已过期；重新登录并替换 Cookie |
| 疑似风控 | 暂停频繁刷新，稍后再试；应用不会绕过验证码或平台控制 |
| 网络错误 | 检查网络后重试；收藏会保留，状态维持“未知” |
| 响应格式变化 | 平台接口可能已调整，需要更新解析；不会误报成“未开播” |
| 主播未开播 | 已成功识别主播，但当前没有直播场次 |
| 无可播放流 | 当前直播响应里没有通过域名和格式校验的 FLV/HLS 地址 |

## 维护说明

后端实现位于 `src-tauri/src/platforms/xiaohongshu/`：

- `credential.rs`：Cookie 校验、系统安全存储和会话存储；
- `input.rs`：输入分类、短链接和域名白名单；
- `signing.rs`：请求签名；
- `client.rs`：用户搜索、身份解析和状态刷新；
- `stream.rs`：当前直播间与响应内播放地址提取。

前端实现位于 `web/src/platforms/xiaohongshu/`，共享关注、播放器、导出和同步逻辑仍在原有全局模块中。维护时必须保持以下约束：固定用户 ID 不得被动态 `roomId` 覆盖；网络、认证、风控和响应异常必须保持 `UNKNOWN`，不能映射成离线；播放地址必须来自当前响应，不能仅按 `roomId` 拼接 CDN URL；新增序列化字段前必须经过公开字段白名单。

## 验证边界

自动测试覆盖 Cookie 解析和脱敏、输入解析、精确匹配、动态房间更新、播放地址提取/去重/域名限制、代理请求头范围、错误分类、关注导入导出和局域网合并。前端生产构建和 Rust 编译也在此分支验证。

真实登录接口、正在直播的画面/声音、Cookie 过期和风控响应仍需要由用户在本机应用界面中使用自己的账号验证。没有个人 Cookie 或真实直播条件时，不应把模拟数据和编译通过描述为“实际播放成功”。
